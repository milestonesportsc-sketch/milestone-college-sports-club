Server Security & Access Control · Central Security Management

Every person signs in at admin.html and is sent to their own page. The server decides what each role may read and write, so a role cannot go beyond this table even by editing the page. Only the Database Administrator manages accounts, backups, the database and server security.

What the security alarm covers: sign-in attacks and account security (wrong passwords, unknown accounts, lock-outs, blocked networks, intruder photo and email alerts). It is not a network intrusion detection system, a firewall manager or a server malware scanner.

A backup is a full copy of the database file (club data, accounts, activity log). Backups contain password hashes: keep downloaded files private. "Restore" brings back the club data only; accounts and passwords are never changed by a restore, and a safety copy is made first. The newest 30 backups are kept. Photos live in the uploads folder, which is not part of the database file.

One place for every alarm, notification, signed-in device and blocked network of the website. Each line shows whether that protection is working right now.

📱 Alarm phones · SMS and Telegram photo

Photo straight to the phone (Telegram bot)

SMS cannot carry a picture, so the intruder photo goes by Telegram. 1) In Telegram open @BotFather, send /newbot, copy the token here. 2) On each phone open your new bot and press Start. 3) Press Find chat IDs and tap a name to put its ID in a number card above. 4) Save, then press the test button.

What happens on an alarm: every number gets an SMS at once, then a reminder every 3 minutes (up to 40) until the Database Administrator or Club President presses STOP ALARM. Telegram also gets the photo. SMS sending needs SMS_URL in the server .env file.

Alert email (automatic)

Gmail: turn on 2-step verification, then create an App password in your Google account and paste it here. Once saved, every alarm, new-device notice and intruder photo is emailed automatically to every active account and to the extra addresses above.

How the alarm worksEvery wrong password (or unknown email) is recorded here at once. Everyone who is signed in sees a flashing red alarm with a siren, and every active account gets an email if the mail server is set up (SMTP_* in .env).

Signed-in devices (every phone, laptop and browser)

Every sign-in is listed here with its device, network and last activity. Remove signs that device out immediately. A new, never-seen device is marked NEW and an email goes to every account.

New-device approval mode

When ON, anyone (except the Database Administrator) who enters the correct password on a new device is not let in until you press Approve below. Devices already in use stay allowed, and a person's very first device is allowed automatically.

Blocked devices

A blocked device cannot sign in again, even from another network. Allow again gives permission back.
